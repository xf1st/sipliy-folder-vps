# Лог разработки проекта VPS Downloader («CloudSpace»)

Этот документ содержит полную историю изменений, архитектурных решений, реализованных возможностей и диагностических шагов по проекту. Он создан для того, чтобы любой разработчик или AI-ассистент (например, Codex) мог мгновенно погрузиться в контекст проекта и продолжить работу.

---

## 📋 Общие сведения о проекте
* **Название приложения**: CloudSpace (VPS Downloader)
* **Технологический стек**: Node.js (Express), HTML5, Vanilla JS (ES5-совместимый для старых браузеров), CSS3 (кастомные переменные и премиальный темный интерфейс).
* **Основной файл сервера**: `app/server.js` (содержит как эндпоинты API, так и шаблон рендеринга страницы `cloudPage`).
* **Конфигурация деплоя**: `deploy.config.js` (содержит SSH-реквизиты для деплоя на VPS).
* **Скрипт автоматического деплоя**: `deploy-systemd.js` (собирает клиентское расширение, закачивает файлы по SFTP и перезапускает службу systemd `vps-downloader`).

## 🚀 Реализованные фичи и улучшения

### 1. 🌈 Динамические акцентные темы (Dynamic Accent Themes)
* **Суть**: Ранее цвета были жестко зашиты в CSS-стилях. Мы перевели всю визуальную систему на кастомные CSS-переменные (`--accent-color`, `--accent-glow`, `--accent-hover`, `--accent-bg`, `--accent-light`).
* **Темы**: Добавлено 4 премиальных цветовых схемы:
  * **Violet Glow** (по умолчанию, `#a078ff`)
  * **Emerald Mint** (`#10b981`)
  * **Ruby Crimson** (`#f43f5e`)
  * **Glacier Blue** (`#06b6d4`)
* **Применение**: Клиентская функция `applyAccentColor()` динамически считывает выбранную тему из `localStorage` и применяет CSS-переменные к элементу `body` без перезагрузки страницы.

### 2. 🛡️ Премиум-редизайн настроек с разделением ролей
* **Суть**: Полностью переработан интерфейс страницы настроек (`/cloud#settings`) на современный двухколоночный адаптивный макет `.settings-grid`.
* **Разделение доступа**:
  * **Персональные настройки** (левая колонка): Селектор цветовых тем с интерактивными плашками, форма смены имени и пароля, управление токеном расширения браузера, переключатель системных уведомлений и виджет Speed test.
  * **Системные настройки (Admin)** (правая колонка): Отображаются **строго** при условии `profile.isAdmin === true`. Администратор может настраивать глобальный срок автоудаления файлов (1 день, 3 дня, 7 дней, 30 дней или никогда) и управлять аккаунтами пользователей (создавать, удалять, изменять пароли и роли).

### 3. 🔍 Мгновенные фильтры по категориям файлов (Client-Side Category Filters)
* **Суть**: В панели файлового менеджера под хлебными крошками размещена интерактивная панель фильтров (`Все`, `Изображения`, `Видео`, `Музыка`, `Документы`, `Архивы`).
* **Логика**: Фильтрация выполняется на стороне клиента мгновенно. Директории всегда остаются видимыми, чтобы пользователь не терял навигацию, а файлы фильтруются по расширению. При переходе в другую папку фильтр автоматически сбрасывается на «Все».

### 4. 🔄 Режим плейлистов для медиафайлов (Sibling Media Navigation)
* **Суть**: Добавлена навигация «Предыдущий» и «Следующий» (`navigate_before` / `navigate_next`) в боковую панель предпросмотра и полноэкранный медиа-вьюер.
* **Логика**: Функция `getSiblingMedia(direction)` находит соседние медиафайлы того же типа (картинки, аудио или видео) в текущей директории. При окончании воспроизведения видео или аудио в плеере Plyr автоматически запускается следующий файл из списка.

### 5. 🛠️ Устранение бага с двойным воспроизведением (Plyr Double-Play Fix)
* **Суть**: Исправлена проблема, при которой звук видео/аудио продолжал играть параллельно на заднем фоне при переходе в полноэкранный режим.
* **Решение**: При открытии полноэкранного вьюера объект маленького плеера полностью уничтожается методом `.destroy()`, а его DOM-узел очищается. При закрытии полноэкранного вьюера маленький плеер воссоздается заново на той же секунде воспроизведения.

### 6. 📄 Клиентская подсветка синтаксиса (Dracula-Style Regex Highlighter)
* **Суть**: Добавлен ES5-совместимый парсер синтаксиса `highlightCode(code, ext)` с Dracula-стилизацией для форматов `.js`, `.json`, `.css`, `.html`, `.py`, `.sh`, `.yml`, `.yaml`, `.md`.
* **Защита**: Установлено строгое ограничение размера файла в 150 КБ для предотвращения зависания интерфейса на слишком больших файлах.

### 7. 🔑 Защита публичных ссылок паролем
* **Суть**: Добавлена возможность защитить паролем создаваемые публичные ссылки.
* **Безопасность**: На сервере хэширование пароля производится с использованием уникальной криптографической соли для каждой ссылки через `crypto.pbkdf2Sync` (SHA-256, 10000 итераций).
* **Страница авторизации**: При переходе по защищенной ссылке `/share/:token` пользователь видит стильную форму ввода пароля. Админ в менеджере ссылок видит статус защиты (🔒/🔓) и может менять или полностью сбрасывать пароль.

### 8. 📦 Потоковая ZIP-архивация папок «на лету» (Streaming Folder ZIP)
* **Суть**: Ранее скачать папку целиком было невозможно. Мы интегрировали библиотеку `archiver`.
* **Решение**: При запросе скачивания папки сервер генерирует ZIP-архив в режиме реального времени и транслирует его напрямую в HTTP-ответ (`res`). Это полностью исключает создание временных файлов на диске VPS и экономит место.

### 9. 📋 Быстрая загрузка из буфера обмена (Ctrl + V)
* **Суть**: Возможность мгновенно вставить скопированный файл (например, скриншот) в активную директорию.
* **Решение**: Глобальный перехватчик события `paste` на клиенте автоматически определяет наличие файлов в Clipboard. Добавлен фильтр, исключающий перехват при вводе текста в поля (`INPUT`, `TEXTAREA` или `isContentEditable`). Если файл не имеет имени (как скриншоты в Windows), ему присваивается имя `Screenshot_YYYYMMDD_HHMMSS.png`.

## ⚡ Оптимизация производительности и исправление зависаний (Performance & Bug Fixes)

### 10. Устранение блокировок Event Loop (CPU-интенсивные задачи)
* **Проблема**: В эндпоинтах `/api/fm/search` и `/api/fm/meta` использовался синхронный рекурсивный обход папок `fmDirSize` для вычисления размера каталогов. При наличии больших папок (например, `node_modules` или корень диска) сервер Node.js зависал на десятки секунд, блокируя весь Event Loop и вызывая ошибку загрузки во всех вкладках всех пользователей.
* **Решение**: Полностью вырезали синхронный просчет `fmDirSize` для папок из этих эндпоинтов.
* **Отображение**: Для директорий на клиенте в списке теперь выводится красивый прочерк `—` вместо неточного `0 B`, а в режиме сетки и предпросмотра отображается количество дочерних объектов.

### 11. Кроссплатформенный виджет свободного места
* **Проблема**: Запрос свободного дискового пространства `/api/disk` запускал внешнюю утилиту `df -h` в терминале Linux. На Windows-системах разработчиков это вызывало постоянные ошибки 500 и падения.
* **Решение**: Переписали сбор информации с использованием кроссплатформенного Node.js API `fs.statfsSync(path)`. Это ускорило работу и устранило сбои.

### 12. Исправление критической ошибки JS на клиенте (SyntaxError)
* **Проблема**: В регулярных выражениях подсветки синтаксиса `highlightCode` на сервере было прописано избыточное экранирование бэкслешей (четыре обратных слэша `\\\\`). Это транслировалось в браузер как невалидный синтаксис вида `temp=temp.replace(/\\/\\*[\\s\\S]*?\\*\\//g, ...)` (второй слэш не экранировался и закрывал RegExp раньше времени). Движок V8 в браузере падал с критической ошибкой `SyntaxError: Invalid regular expression flags`, полностью отключая обработчики событий страницы (не работали клики по кнопкам, настройки не открывались, висел экран «Загрузка...»).
* **Решение**: Исправили регулярные выражения на корректное однократное экранирование:
  * Блочные комментарии: `'temp=temp.replace(/\\/\\*[\\\\s\\\\S]*?\\*\\//g, ...'`
  * Однострочные комментарии: `'temp=temp.replace(/\\/\\/.*$/gm, ...'`
  * Теги HTML: `'temp=temp.replace(/(&lt;\\/?)([\\\\w:-]+)(.*?)(\\/?&gt;)/g, ...'`
  * Границы слов и классы символов: `\b`, `\d`, `\w` на клиенте теперь передаются как корректные регулярные выражения (например, `\\b` в Node JS строке для генерации `\b` на клиенте).

## 🧪 Диагностика и верификация клиентского кода
Для проверки корректности генерации страниц и синтаксиса JavaScript без запуска полноценного браузера мы создали инструмент:
* **Файл**: `check_client_syntax.js`
* **Принцип работы**: 
  1. Выполняет серверный рендеринг страницы через `cloudPage()`.
  2. Извлекает все блоки `<script>` из HTML-кода.
  3. Вызывает компилятор `new vm.Script(scriptCode)` из встроенного модуля Node.js `vm`.
  4. Если в коде есть синтаксические ошибки, они выводятся с точным указанием строки и контекста ошибки.
* **Текущий статус**: Все скрипты успешно проходят валидацию!

## 🚀 Процедура деплоя на VPS
Скрипт `deploy-systemd.js` выполняет автоматизированную выкатку на боевой сервер:
1. Архивация клиентского расширения (`extension/*`) в архив `extension.zip` (используя PowerShell на Windows или `zipfile` на других ОС).
2. Подключение по SSH на порт `2222` к серверу `77.73.135.98` (пользователь `root`).
3. Закачка файлов `server.js`, `package.json`, `package-lock.json` и `extension.zip` в каталог `/opt/vps-downloader`.
4. Удаленная установка чистых продакшн-зависимостей через `npm ci --omit=dev`.
5. Проверка синтаксиса на сервере через `node --check server.js`.
6. Перезапуск системной службы `systemctl restart vps-downloader` и проверка ее статуса.

## 📦 Релиз v2.21.0 (30 июня 2026)

### Что изменилось

#### 🗂 Исправлено досрочное удаление файлов (File Persistence Fix)

**Проблема:** Функция `runCleanup` удаляла файлы ориентируясь только на `mtime` (время последней модификации на файловой системе). Если у файла был старый `mtime` — например, скачанное медиа с оригинальной датой видео, или файл скопированный с сохранением даты — он мог исчезнуть раньше срока retention даже если был только что добавлен в систему.

**Решение:**

- `registerUploadedFile` в `db.js` теперь сохраняет timestamp регистрации (`Date.now()`) вместо булевого `true` в `uploads.json`.
- Добавлена функция `getUploadedFileTs(username, filename)` — возвращает timestamp регистрации файла.
- `runCleanup` в `server.js` теперь вычисляет эффективный возраст файла как `max(mtime, registeredAt)`. Файл не будет удалён раньше чем через N дней с момента, когда он реально появился в системе.
- При завершении yt-dlp задачи (`media.js`) скачанный файл теперь явно регистрируется в `uploads.json` — аналогично загрузке с ПК.

**Затронутые файлы:** `app/db.js`, `app/server.js`, `app/media.js`
